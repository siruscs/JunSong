# 财务概览经营驾驶舱设计

## 目标

将财务概览从长页面指标堆叠改造成面向店长和财务负责人的经营驾驶舱：先判断经营结果，再处理风险待办，随后查看趋势，最后进入专题报表。

## 设计原则

- 只使用当前财务模块已有接口和路由，不伪造后端指标。
- 保留门店范围、时间粒度、权限失败、加载失败和刷新能力。
- 核心指标突出销售、毛利、现金流、应收；费用、借支、库存、分润和核算周期进入处理队列。
- 六类报表入口集中呈现：销售经营分析、利润分析、费用异常、分润结算、库存价值与对账、门店经营分析。
- 后端权限仍是最终授权来源，前端入口不替代权限校验。

## 页面结构

1. 页头：标题、当前数据时间、门店筛选、时间粒度、查询/刷新。
2. 经营结论：本期销售、毛利润、毛利率、现金净流入、期末应收余额。
3. 风险待办：费用核销、借支核销、逾期应收、库存异常、待分润、核算周期/锁账状态。
4. 趋势与排行：销售/利润/现金流趋势摘要，门店销售和利润排行。
5. 经营预警与复盘任务：复用现有预警、任务接口和后端返回跳转。
6. 报表工作台：六个真实路由入口，展示用途说明。

## 交互与状态

- 查询时显示局部加载状态，失败时保留页面结构并展示可重试提示。
- 权限不足时显示权限状态页，不展示误导性零值。
- 没有待办或预警时显示明确的健康空状态。
- 所有入口使用现有动态路由，报表页面继续自行执行权限校验。

## 验收标准

- 页面结构按“结论 → 待办 → 趋势 → 报表”呈现。
- 六个报表入口全部可见且路由真实存在。
- 当前财务概览接口调用保持兼容，门店和时间查询行为不变。
- 构建通过，静态验收脚本通过。
- 设计和验收结果分别记录在 `docs/superpowers/specs/` 与 `docs/superpowers/reports/`。
