# AGENTS 上下文精简与 Nacos V3 约束设计

## 目标

在不削弱安全、财务和部署边界的前提下，减少 `AGENTS.md` 每次自动加载的 Token；同时彻底禁止 Agent 错误调用 Nacos V1 API。

## 信息分层

`AGENTS.md` 只保留所有任务都需要的内容：项目地图、技术基线、安全边界、工作方法、完成标准、按任务读取的文档索引，以及 Nacos V3/SQL/PROD 的高风险约束。费用核销细则和部署命令等长内容由权威专项文档承载，Agent 仅在命中相应任务时读取。

不得把以下规则移出根文件：后端鉴权权威、租户/部门隔离、财务原子性与并发、锁定/结转禁止反核销、UTF-8 SQL、嵌套小程序仓库、GitNexus 提交检查、脏工作区保护。

## Nacos V3 约束

- DEV/PROD 均按 Nacos V3 处理，禁止调用 `/nacos/v1/**`。
- 使用 API 前必须从 V3 文档或运行实例验证端点；不得凭记忆猜测路径。
- V3 API 返回 401/403/404 时停止，不得自动降级到 V1，也不得立即绕过 API 直改数据库。
- 配置发布优先使用项目中经验证的 V3 发布入口。若入口缺失，先诊断并获得明确授权。
- PROD 修改前备份 `junsong-config.config_info`；发布后核对内容/MD5，重启受影响组件，并通过真实域名/API 验证。
- 直接修改 Nacos 配置库仅作为明确批准的应急手段，必须备份、窄更新、核对两个历史 namespace 记录并记录回滚方法。

## Token 优化方法

- 合并重复规则，短句化，不重复解释理由。
- 用任务路由表替代常驻专项细则。
- 保留命令模板的入口，不在根文件重复部署手册中的长命令。
- 删除会自动变化或可即时发现的状态信息，如符号数量、运行状态和历史会话摘要；由工具实时查询。
- 目标：根文件词数较当前减少至少 30%，且专项规则测试仍可定位到权威文档。

## 验证

- 增加静态契约：根文件和部署文档必须声明 Nacos V3、禁止 `/nacos/v1/`、要求备份与验证。
- 检查 `AGENTS.md` 词数下降比例。
- 独立审查是否遗漏安全、财务、部署或 Git 边界。
