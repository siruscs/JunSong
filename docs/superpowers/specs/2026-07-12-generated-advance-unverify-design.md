# 核销生成借支反核销修复设计

## 问题

费用 40 元使用未核销借支 100 元核销后，系统将原借支置为已核销，并生成 60 元未核销节余借支。数据库 `fin_advance.verify_by` 默认值为 `''`；新增借支映射没有写入 `verify_by/verify_time`，因此节余记录在 Java 中表现为空字符串，而反核销只接受 `null`，错误提示“借支核销信息已变化”。同一遗漏还会使系统生成的已核销补款缺少批次核销人和核销时间。

## 选择方案

采用关系类型感知的状态校验，并修正新增借支持久化：

- `SURPLUS`：必须保持未核销状态；`verify_by` 的 `null` 和空白字符串均表示未核销，`verify_time` 必须为空。
- `SUPPLEMENT`：必须保持已核销状态，核销人和核销时间必须与核销批次一致。
- `SOURCE`：维持现有严格校验，必须是本批次核销形成的已核销状态。
- `insertFinAdvance` 显式写入 `verify_by` 和 `verify_time`，使未来生成的补款保存完整批次元数据，节余保存 SQL `NULL`。

## 不变边界

- 已锁定、待结转或已结转周期仍禁止反核销。
- 生成借支已被后续业务使用时仍禁止反核销。
- 反核销仍整批、原子恢复费用和来源借支，并逻辑失效生成借支。
- 租户、部门、批次快照和乐观并发条件不变。

## 验证

- 新增完整回归：来源借支 100、费用 40、生成节余 60，数据库返回空字符串核销人时可反核销。
- 断言费用与来源借支恢复、节余借支失效、批次反核销成功。
- 保留并运行补款、下游引用、周期锁定及全部费用核销服务回归。
