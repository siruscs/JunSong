# 小程序核算周期经营 V1 设计说明

**目标**：将小程序首页从日经营信息入口升级为以当前核算周期回本和净利为核心的经营入口，并补强登录态恢复和前台恢复能力。

## 版本范围

本次 V1 开发分支包含 V1.0、V1.1、V1.2 三个阶段。阶段按顺序执行，每个阶段先完成测试和代码审查，再进入下一阶段；未完成阶段不得混入下一阶段的功能。

### V1.0：经营核心与稳定性

包含：登录态恢复、Token 刷新、核算周期首页、店长/主管/投资人按角色展示回本和净利、首页请求节流、核算周期数据缓存、统一接口响应处理、字典缓存、部门切换竞态保护。

### V1.1：库存和表单能力

包含：库存流水分页筛选、多商品库存调整、库存调整全流程幂等、草稿自动保存、表单模块组件化、统一加载/空数据/错误状态组件。

### V1.2：权限与技术债

包含：页面权限统一守卫、后端能力驱动按钮、秒杀统计批量接口、Vite 运行时 patch 文档化和升级验证、统一错误上报。

## V1.0 核心主线

1. 登录态稳定：小程序冷启动、回到前台、被系统回收后，优先恢复本地会话并刷新即将过期的 Token，刷新失败才要求重新登录。
2. 核算周期首页：店长、主管、投资人进入后优先看到实际缴款、周期成本、净利、回本差额、回本进度和应收信息；日销售、现金流、秒杀等降为辅助信息。

库存和表单能力、权限与技术债不提前混入 V1.0；V1.0 的字典缓存、接口响应归一化、首页节流和部门切换保护属于经营首页稳定性的一部分。

## 角色视图

- 店长：本店当前周期净利、回本差额、待核销费用、待核销借支、欠款回收。
- 主管：授权门店周期净利和回本进度汇总，门店异常入口。
- 投资人：授权范围周期净利、投资人分润和可结算状态。
- 记账员：保留录入和待办工作台，不默认展示复杂经营判断。

## 统一口径

```text
周期净利 = 实际缴款收入 - 已核销费用 - 进货款 - 未核销借支
回本差额 = max(周期成本 - 实际缴款收入, 0)
回本进度 = 实际缴款收入 / 周期成本 * 100%，周期成本为 0 时显示 --
```

后端返回当前授权范围的周期摘要，前端只负责展示，不在客户端重新拼接业务数据。没有授权部门或当前周期时，页面显示明确空状态，不回退到全门店或月度数据。

## 数据流

```text
启动/回前台
  -> 恢复本地会话
  -> 检查 access token
  -> 必要时 refresh token
  -> 拉取授权部门和当前周期摘要
  -> 根据角色渲染周期经营首页
```

接口失败时保留最近一次成功摘要，并显示“数据更新时间”；首次加载失败显示可重试空状态。401 只允许统一会话层处理一次，避免多个页面同时跳登录。

## 验收标准

- WJS 连续数小时离开小程序后重新进入，不因 access token 正常过期直接回登录页；refresh 失败时才重新登录。
- 店长首页第一屏能看到当前周期净利和回本差额，数值与 PC 核算周期一致。
- 主管只能看到授权门店，投资人只能看到授权范围，不出现跨部门数据。
- 周期成本包含已核销费用、进货款、未核销借支；销售额不作为收入指标。
- 无当前周期、无部门授权、接口超时时，均有明确状态，不展示误导性的 0 元正常数据。
- 后端单元测试、前端构建、小程序构建和专项静态检查通过。

## 阶段门禁

1. V1.0 门禁：周期首页、会话恢复、缓存和请求竞态专项测试通过；FILE 服务启动问题完成定位并恢复可用；部署 DEV 后等待人工验收。
2. V1.1 门禁：库存和表单专项测试、微信构建、库存单据幂等和权限回归通过；不改变 V1.0 周期利润口径。
3. V1.2 门禁：权限守卫和后端能力接口回归通过，技术债文档和统一错误上报验证通过；全部阶段完成后才提交合并评审。
