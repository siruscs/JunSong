# PROD 工作流、低代码菜单与参数乱码修复设计

## 现状

- PROD `sys_menu` 中“工作流中心”和“低代码平台”及其权限记录均为 0。
- Flowable 的 `act_*`、`flw_*` 表已存在，说明工作流基础数据库已部署，缺失点是系统菜单与授权。
- PROD 不存在 `SYS_PARAMETER` 表；用户所指参数管理实际为 `sys_config`。
- `sys_config` 中六个 R22/R23 参数的 `config_name` 和 `remark` 为 UTF-8 被 latin1 二次编码的乱码，其他参数正常。

## 修复方式

新增一份仅处理菜单、授权和六个参数键的 UTF-8 幂等 SQL：

1. 使用当前空闲且仓库历史约定的稳定 ID 区间恢复工作流中心（根 ID 2220）和低代码平台（根 ID 2280）。
2. 工作流菜单与当前 PC 页面、权限码一致，包含定义、发起、实例、任务、历史、分析、超时、版本、字段权限、实例干预和监控。
3. 低代码菜单包含配置后台、业务单据入口、报表权限及 meta/biz/report 操作权限；动态业务菜单继续挂到根目录。
4. 使用 `role_key='admin'` 授权，不依赖角色 ID。
5. 使用六个稳定 `config_key` 精确更新参数名称和备注，不做整表转码。
6. SQL 以 `SET NAMES utf8mb4;` 开头，通过 `bin/deploy-sql.sh` 执行，部署前自动备份。
7. 输出菜单、授权、参数文字与 HEX 核对结果，执行后只清理菜单和参数相关缓存。

## 安全边界

- 不修改工作流、低代码业务表和数据。
- 不修改 Nacos、网关、服务 JAR 或 PC 静态资源。
- 不删除现有菜单和角色授权；仅按稳定 ID/权限码补齐或纠正目标记录。
- 非管理员角色不自动获得两大后台模块权限。
- 重复执行不得产生重复菜单、重复授权或额外参数变更。
