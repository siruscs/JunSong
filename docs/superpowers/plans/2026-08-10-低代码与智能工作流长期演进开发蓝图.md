# 低代码与智能工作流长期演进开发计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将峻松云现有的 Flowable 工作流与低代码能力，长期演进为普通业务人员可以用业务语言配置、可视化验证、人工确认发布，并能由 AI 持续解释和优化的领域业务编排平台。

**Architecture:** 以统一业务模型作为稳定中间层，业务对象、字段、页面、流程、规则、动作、权限和分析配置先汇聚成版本化模型，再编译为 Flowable BPMN、运行时页面和业务执行策略。AI 只生成和解释业务模型草稿，不直接发布 BPMN、财务动作或权限变更；所有配置必须经过静态校验、模拟运行、人工确认、审计和回滚。

**Tech Stack:** Java 17、Spring Boot 4、Flowable 8.0.0、MyBatis、MySQL、Redis、Nacos V3、Vue 3、TypeScript、Vite、Pinia、Element Plus、bpmn-js、现有低代码 Schema/Runtime 组件。

---

## 一、产品边界与长期目标

产品定位不是通用低代码平台，而是面向零售、门店、会员、库存和财务场景的 AI 业务编排平台。第一批核心场景固定为费用报销、借支核销、采购申请、库存调整、门店开业、会员退款和供应商准入。

最终用户体验：

```text
业务人员描述需求
  → 选择业务模板或让 AI 生成草稿
  → 确认业务对象、表单、流程、规则、权限
  → 可视化预览与测试数据模拟
  → 静态校验与风险提示
  → 人工确认发布
  → 运行监控、异常解释、流程优化建议
```

硬约束：

- AI 不直接发布生产配置，不直接执行任意 SQL、JavaScript 或财务变更。
- 后端权限、租户、部门范围、财务期间和审计规则优先于页面配置。
- 业务配置必须有草稿、版本、发布、回滚和差异对比。
- 简易模式面向普通人，专业模式面向实施人员；两者生成同一份统一业务模型。
- 每个阶段必须有可演示闭环和退出条件，不以“代码完成”作为完成标准。

## 二、现状基线

已有后端能力：

- `junsong-modules/junsong-workflow/src/main/java/com/junsong/workflow/lowcode/domain/` 已包含业务对象、字段、页面 Schema、动作、分支规则、节点处理人、定时器和后置动作模型。
- `lowcode/metadata/` 已有发布前元数据校验。
- `lowcode/runtime/` 已有运行时页面组装和字段策略。
- `lowcode/service/` 已有流程组装、配置版本、实例、模板、报表和 Excel 能力。
- `lowcode/protocol/` 已有工作流命令校验与分发。

已有前端能力：

- `junsong-ui-v3/src/views/workflow/designer/index.vue` 提供 BPMN 设计、导入、导出和部署。
- `junsong-ui-v3/src/views/lowcode/designer/FormDesigner.vue` 提供表单设计。
- `junsong-ui-v3/src/views/lowcode/admin/` 提供业务对象、配置、模板、发布和版本入口。
- `junsong-ui-v3/src/views/lowcode/fields/` 提供运行时字段和子表单渲染。
- `junsong-ui-v3/src/views/workflow/start/index.vue` 已根据已发布业务对象加载运行时表单并发起流程。

主要缺口：

1. 低代码后台仍以技术配置为主，缺少面向业务人员的业务向导。
2. 表单、流程、规则、权限和菜单之间缺少统一的可视化确认页面。
3. 简易流程画布和专业 BPMN 画布没有分层。
4. 缺少测试数据模拟、配置影响分析和发布前风险报告。
5. 模板中心尚未形成完整的业务场景资产。
6. 没有受控的 AI 业务模型生成、解释、修复和优化闭环。

## 三、分阶段开发计划

### 阶段 0：基线治理与统一业务模型

**目标：** 明确现有对象之间的关系，建立稳定的版本化业务模型边界，不立即增加 AI。

**主要文件范围：**

- 后端：`junsong-modules/junsong-workflow/src/main/java/com/junsong/workflow/lowcode/domain/`、`domain/dto/LcBizConfigDTO.java`、`metadata/`、`service/`、`mapper/`。
- 前端：`junsong-ui-v3/src/api/lowcode/`、`src/views/lowcode/admin/`、`src/views/lowcode/schema.ts`。
- 测试：`junsong-modules/junsong-workflow/src/test/java/com/junsong/workflow/lowcode/`。

**交付内容：**

- 明确 `BusinessApp → Object → Field/Page/Workflow/Rule/Action/Permission` 的统一关系。
- 配置草稿、发布版本、快照、回滚和差异读取接口统一。
- 发布时输出影响范围：表单、流程、菜单、权限、数据表和已有实例。
- 补齐版本号、乐观锁、租户范围和发布状态校验。

**退出条件：** 一个费用报销配置可以一次性读取、编辑、校验、保存草稿、发布、回滚，并在前端重新加载后保持一致。

### 阶段 1：模板中心与业务配置向导

**目标：** 让普通用户从模板开始配置，而不是从空白页面开始。

**主要文件范围：**

- 前端新增：`junsong-ui-v3/src/views/lowcode/wizard/`、`src/views/lowcode/templates/`、`src/views/lowcode/preview/`。
- 前端复用：`src/views/lowcode/designer/FormDesigner.vue`、`src/views/workflow/start/index.vue`、`src/views/workflow/designer/index.vue`。
- 后端扩展：`lowcode/service/LcTemplateService.java`、`LcMetadataService.java`、`controller/`、模板 Mapper/XML。

**配置向导固定步骤：**

1. 选择业务场景。
2. 确认业务对象和字段。
3. 配置审批角色。
4. 配置金额或状态分支。
5. 配置通知、超时和自动动作。
6. 预览表单、流程和权限。
7. 校验并保存草稿。

**首批模板：** 费用报销、采购申请、库存调整、门店开业、会员退款。

**退出条件：** 非开发人员可以在 10 分钟内基于费用报销模板完成字段、审批角色和金额分支配置，不接触 BPMN XML 或表达式。

### 阶段 2：简易流程画布与模拟运行

**目标：** 将 BPMN 专业设计器与普通业务画布分层，提供“提交、审批、判断、通知、更新、结束”等有限节点。

**主要文件范围：**

- 前端：`junsong-ui-v3/src/views/workflow/designer/index.vue`、新增 `src/views/workflow/simple-designer/`、`src/views/workflow/simulation/`。
- 后端：`lowcode/service/LcWorkflowAssembleService.java`、`BpmnMultiInstanceAssembleService.java`、`BpmnTimerAssembleService.java`、`service/definition/`。
- 测试：低代码流程组装、分支、会签、定时器和模拟运行测试。

**关键规则：** 简易画布产出统一业务模型，由后端编译为 BPMN；专业模式仍支持高级 BPMN，但必须通过相同的安全校验。

**退出条件：** 费用报销流程可以用简易画布完成配置，并使用至少 3 组测试数据模拟通过、驳回和金额分支路径，输出每一步变量变化和审批人。

### 阶段 3：发布治理与运行分析

**目标：** 让配置发布可审计、可解释、可回滚，并能用运行数据发现流程问题。

**主要文件范围：**

- 后端：`lowcode/service/LcConfigVersionService.java`、`LcReportService.java`、`LcInstanceService.java`、`controller/LcReportController.java`。
- 前端：`junsong-ui-v3/src/views/workflow/version/`、`history/`、`analytics/`、`monitor/`、`intervene/`。

**交付内容：**

- 配置差异对比和发布影响报告。
- 节点耗时、积压、驳回率和分支命中率分析。
- 发布前风险分级：阻断、警告、提示。
- 运行中配置版本与业务实例绑定，禁止隐式改变历史实例。

**退出条件：** 管理员可以回答“本次发布改变了什么”“影响哪些流程和菜单”“当前哪些节点积压”“如何回滚”。

### 阶段 4：AI 副驾驶

**目标：** AI 生成业务模型草稿、解释配置和发现问题，但不越过人工确认。

**主要文件范围：**

- 后端新增：`junsong-modules/junsong-workflow/src/main/java/com/junsong/workflow/lowcode/ai/`，包含模型适配、提示模板、结构化输出校验、权限裁剪和审计。
- 前端新增：`junsong-ui-v3/src/views/lowcode/assistant/`，复用向导、预览、校验和版本组件。
- 安全测试：AI 输出越权、跨租户数据泄露、未授权动作、财务字段变更和提示注入测试。

**首批 AI 能力：**

- 根据业务描述生成草稿。
- 解释现有表单、流程和规则。
- 发现空处理人、无效分支、字段未绑定和权限冲突。
- 生成测试数据与测试场景。
- 根据用户修改生成差异说明。

**退出条件：** AI 能生成费用报销草稿，并输出结构化差异、风险提示和人工确认清单；任何未确认草稿不能进入发布接口。

### 阶段 5：AI 业务编排与运行时智能化

**目标：** AI 能跨业务对象、表单、流程、规则、通知和报表编排完整业务方案，并基于运行数据提出优化建议。

**主要文件范围：**

- 后端：`lowcode/ai/`、`lowcode/runtime/`、`lowcode/event/`、`lowcode/service/LcReportService.java`，增加只读分析工具和受控业务工具。
- 前端：AI 助手、运行分析、异常解释、优化建议和人工批准面板。
- 运维：审计日志、模型调用记录、脱敏策略、提示版本和 AI 输出回放。

**退出条件：** 对一个已运行的业务流程，AI 能根据真实数据解释瓶颈、提出可执行变更草稿，并通过模拟、审批和版本发布完成闭环。

## 四、每次开发的强制流程

每个任务必须遵守：

1. 先阅读本计划和跟踪文档，确认所属阶段及退出条件。
2. 调研真实代码路径，必要时运行 GitNexus `query`、`context` 和上游 `impact`。
3. 先写失败测试，再实现最小变更。
4. 运行模块测试、前端构建或契约测试。
5. 做权限、租户、部门、财务和版本影响检查。
6. 更新 `docs/superpowers/tracking/2026-08-10-低代码与智能工作流长期演进跟踪.md`。
7. 在跟踪文档记录完成项、验证结果、遗留问题、偏差和下一步。
8. 只提交任务相关文件，提交前执行 `git diff --cached --check` 和 GitNexus `detect_changes(scope="staged")`。

## 五、明确不做的事情

- 不把产品扩展为任意行业的无限制通用低代码平台。
- 不允许 AI 直接执行任意 SQL、脚本、权限提升或财务记账动作。
- 不在没有统一业务模型之前建设复杂 AI Agent 市场。
- 不用大量新页面替代现有共享运行时表单和组件。
- 不以“节点数量多”作为低代码产品成熟度指标。
