# 财务库存与小程序能力修复设计

## 范围

本轮修复覆盖五个用户问题：财务概览布局与六个入口 404、期初库存空白、库存成本调整不生效、小程序库存与成本只读模块、小程序缴款修改入口。

## 方案

### 1. PC 财务概览

将标题、说明和刷新按钮收敛为同一行；删除没有业务信息的独立说明区。六个报表入口统一使用已存在页面，并补齐前端固定路由，动态菜单仍负责权限和显示。

### 2. 期初库存

固定挂载 `/finance/stockInit/index` 页面，统一其父级路由、`activeMenu`、组件路径和动态详情路由；页面加载按现有 `/stockInit` API 的响应结构解包，权限不足显示明确状态。

### 3. 成本调整

核对 `/report/stock/cost-adjustment` 的请求、权限、成本台账写入和库存价值查询。调整成功必须刷新库存价值结果，并保留幂等、租户、门店和期间校验，不通过前端直接修改库存数量。

### 4. 小程序库存与成本

新增 `stockCost` 模块权限配置和只读页面。页面展示授权门店的库存数量、库存金额、商品筛选和库存流水入口；使用 `finance:report:stock` 读取权限，前端隐藏不能替代后端权限校验，不开放盘点、成本调整、过账。

### 5. 小程序缴款修改

在销售/缴款记录中增加修改入口，复用现有 `PUT /finance/sale/payment/{paymentId}`，编辑缴款日期、金额、付款方式和备注；成功后刷新销售记录、缴款汇总和应收状态，保留权限与周期规则。

## 验收标准

- 六个报表入口不再进入前端 404 页面。
- 期初库存列表可加载，详情跳转正常。
- 成本调整成功后库存价值/成本结果可观察到变化或明确拒绝原因。
- 无库存模块权限的小程序用户看不到入口且直接访问被拒绝。
- 有权限用户可查看库存数量、金额和流水，但不存在写操作按钮。
- 小程序可编辑缴款并在成功后刷新相关数据。
- 每个阶段都有测试结果和本地 Git 提交，不推送远程。
