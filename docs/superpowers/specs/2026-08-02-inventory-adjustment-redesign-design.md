# 库存调整重构设计

## 目标

将现有“期初库存”能力重构为“库存调整”，支持多种库存调整业务类型，并让库存流水的 `change_type` 真实反映业务原因；同时修复 PROD 小程序模块权限下发问题，并让财务总览复用系统首页当前核算周期统计。

## 业务规则

库存调整数量始终填写正数，系统根据调整类型决定库存方向：

| 调整类型 | 编码 | 方向 |
|---|---|---|
| 期初库存录入 | `OPENING_STOCK` | 增加 |
| 历史数据补录 | `HISTORY_REPLENISH` | 增加 |
| 试用消耗 | `TRIAL_CONSUMPTION` | 减少 |
| 店面自用 | `STORE_USE` | 减少 |
| 报损 | `DAMAGE_LOSS` | 减少 |
| 其他 | `OTHER` | 用户选择增加或减少 |

类型名称由系统字典配置，前端不硬编码展示文案；后端以编码和方向规则为准，防止客户端篡改方向。

字段规则：

- “期初日期”改名为“调整日历”，写入库存流水业务日期。
- 商品选择后默认带入商品进价作为单位成本，单位成本允许修改，金额保留 2 位小数。
- 数量保留 3 位小数且必须大于 0。
- 调整金额为数量乘单位成本，金额保留 2 位小数。
- 表单展示当前类型、库存增减方向、数量和预计影响金额；提交前再次确认。

## 系统设计

### 后端

保留现有批次的校验、提交、审批、过账和幂等流程，业务名称和请求字段改为库存调整语义。创建请求增加 `adjustmentType`，`OTHER` 增加 `adjustmentDirection`。过账时由服务端解析字典编码和方向，生成库存流水 `change_type`，不再写死 `STOCK_INIT`；成本流水继续使用与库存方向一致的入库/出库调整类型。

库存流水的业务日期使用 `adjustmentDate`。重复过账仍以批次和明细构造幂等键，调整类型、方向、金额和商品归属均在服务端重新校验。

### PC 端

- 财务菜单由“期初库存”改为“库存调整”，路由保持兼容旧地址并跳转到新页面。
- 表单改用字典接口加载调整类型；类型变化时即时显示增减规则。
- 商品选择后回填进价，单位成本可编辑，数量和金额按精度规则显示。
- 小程序模块权限中增加独立的“库存调整”模块。

### 小程序端

- 会员服务模块定义、管理员授权模块列表和小程序模块配置统一使用 `stockAdjustment`。
- 入口仅在服务端返回该模块权限时显示。
- 小程序库存调整页面只读展示库存调整结果和库存情况，不提供创建、审批或过账。
- 登录后刷新模块能力；若发现旧缓存，则清除模块缓存并重新拉取服务端能力。

### 财务总览

顶部统计区域复用系统首页当前核算周期统计组件和数据源，避免财务总览自行按日/月计算导致口径不一致。

## 安全与数据边界

- 后端权限和租户/门店范围校验为最终依据，UI 隐藏不替代接口鉴权。
- 已过账批次不可修改；调整冲销沿用现有审计和并发保护规则。
- 所有金额使用 `BigDecimal`，数量使用三位小数精度，金额使用两位小数和 `HALF_UP`。
- 字典 SQL 可重复执行并带核对输出；PROD SQL 执行前备份并记录回滚信息。

## 验收标准

1. WJS 在 PROD 重新登录后能看到“库存调整”，无权限账号看不到且接口拒绝访问。
2. 财务总览顶部统计与系统首页当前核算周期统计一致。
3. 六种调整类型均显示正确的增减提示；“其他”必须选择方向。
4. 商品进价自动回填，单位成本两位小数、数量三位小数，调整金额计算准确。
5. 过账库存流水的 `change_type` 等于调整类型对应编码，不再为 `STOCK_INIT`。
6. 库存报表、成本报表和小程序只读库存数据能反映调整结果。
7. 专项测试、前端构建、后端主程序构建通过；DEV/PROD 部署和 SQL 验收记录完整。
