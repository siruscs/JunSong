# PROD Open 路由与菜单图标修复设计

## 目标

恢复 PROD Nacos 缺失的 Open 网关路由，使开放平台应用列表不再被网关当作静态资源，并为动作中心、预测辅助v2、退款申请、版本管理、应用管理五个菜单补齐图标。PC 前端重部署用于确保线上产物与仓库 `/prod-api` 配置一致，不作为 404 根因修复。

## 方案

- 保持后端 `/open/**` 网关路由不变，不新增 Nginx 裸路径兼容，避免扩大公开路由面。
- 使用现有生产配置重新构建并部署 PC 前端，生产 API 基础路径必须为 `/prod-api`。
- 对比 PROD Nacos 实际 `junsong-gateway-prod.yml` 与仓库受控配置；若 `/open/**`、`/openapi/v1/**`、`/openapi/v2/**`、`/openapi/latest/**` 缺失，备份配置表后对齐受控配置并重启 Nacos、网关。
- 以菜单权限码或组件路径作为稳定键，使用 UTF-8、可重复执行的窄 SQL 更新五个菜单的 `icon`。
- 部署后从 PROD 域名验证应用列表请求进入网关，并核对五个菜单图标非空。

## 安全边界

- 不修改菜单层级、权限、路由、可见性和角色授权。
- SQL 通过 `bin/deploy-sql.sh` 执行，部署前备份并强制 utf8mb4。
- 不修改 Open 服务接口及鉴权逻辑。
- 验收以域名 `/prod-api/open/app/list` 返回鉴权响应（无令牌时 401）而非静态资源 404 为准。

## 已确认根因

PC 新产物已正确包含 `/prod-api`，Open 服务 `/app/list` 也已注册。实际 404 来自 PROD Nacos 网关配置漂移：运行配置缺少四条 Open 路由。恢复路由后域名请求由静态资源 404 变为 401，证明请求已进入 API 鉴权链路。
